# ArchiveLoom サイトアダプター実装プロンプト

このファイルは、AIコーディングエージェントへ渡す実装指示書です。利用者はArchiveLoomリポジトリをAIエージェントで開き、対象サイトURLと下記の変数を伝え、この文書を最初から最後まで実行するよう依頼できます。

目的は、保存を許可されたサイトページをArchiveLoomの動画一覧へ変換する、テスト済みサイトアダプターを完成させることです。この文書だけでは、全件ダウンロードの開始を許可しません。

## AIエージェントへの指示

あなたは、ArchiveLoomを特定の1サイトへ対応させます。利用者のArchiveLoomチェックアウト内で作業してください。別のダウンローダーを新規作成したり、無関係なサイトの前提を流用したりしないでください。

変更前に、次のファイルを最初から最後まで読んでください。

1. `docs/engineering-blueprint.ja.md`
2. `docs/adapters.md`
3. `docs/architecture.md`
4. `docs/responsible-use.md`
5. `CONTRIBUTING.md`
6. `src/archiveloom/`配下のアダプターインターフェースとモデル

利用者または実行環境から与えられたリポジトリ固有の指示は、この文書より優先します。

## 利用者が指定する変数

記載のない情報は不明として扱ってください。権限、保存先の安全性、認証、破壊的処理、必要な実装が変わる場合だけ、推測せず利用者へ確認してください。

```text
対象サイトURL: <必須>
保存を許可されている対象と根拠: <必須>
希望範囲: <日付、カテゴリー、チャンネル、ページ、または許可された全件>
選択したい分類: <日付、会場、ステージ、講義、カメラなど>
希望品質: <最高品質、上限解像度、その他>
ファイル名形式: <必須>
保存先ポリシー: <書き込み可能な任意パス、外付けドライブ限定>

実行してよい段階: <調査のみ、実装とテスト、代表1件の試験>
全件ダウンロード開始の明示的許可: <利用者が許可しない限り「いいえ」>
```

## 必須ワークフロー

### 1. 範囲と安全性を確定する

- 起点URLと対象コレクションの境界を確認します。
- 利用者がメディアを所有している、または保存を許可されていると明示していることを確認します。
- DRM、課金、ログイン、CAPTCHA、地域制限、その他のアクセス制御を回避しません。
- 全件ダウンロードは、利用者がその別操作を明示的に許可しない限り開始しません。
- テスト用メディアや一時状態を、利用者が承認した保存先以外へ書き込みません。

### 2. 実際のサイトを調査する

最初は読み取り中心で調査し、次の順序を優先します。

1. 文書化された公開APIまたはフィード
2. 構造化データ、JSON-LD、ページ内のアプリケーション状態
3. 意味が安定したHTML属性とリンク
4. サイト自身がブラウザーから送るネットワーク通信
5. それ以前の方法で不足する場合だけブラウザー自動操作

直接確認できた事項と不明事項を分けて記録し、次を確定します。

- 対応するホストとパスの境界
- コレクション階層とページ送りの終了条件
- 安定した項目ID
- 表示名と選択用分類
- ページURLから直接動画、HLS、DASH URLまでの解決経路
- 必要最小限かつ秘密ではないヘッダー
- URLの有効期限と再解決方法
- DRM、認証、地域制限、削除済み、空一覧、レート制限の判定材料

エンドポイント、DOMセレクター、メディアID、日付、件数、品質、URL形式を推測で作らないでください。

### 3. アダプターを設計・実装する

- サイト発見処理は対象を限定したアダプターへ置きます。
- 選択、並列処理、進捗、再試行、保存先確認、FFmpeg、状態、ロック、完成検証はArchiveLoomを再利用します。
- 実際に対応するURLだけに一致させます。
- 決定的な安定IDとOS間で安全なファイル名を持つ`MediaItem`へ正規化します。
- サイト固有分類は`dimensions`へ入れ、コート、ステージ、日付などをコアへ追加しません。
- 認証情報、Cookie、署名URL、個人情報、実サイトの応答をGitへ保存しません。
- コア変更が必要な場合は理由とテストを分けて示し、アダプター契約を避ける目的でコアを変更しません。

必要に応じてひな型を生成します。

```console
archiveloom adapters scaffold example_site --output ./plugins
```

### 4. 大量実行前にテストする

匿名化され、結果が安定するfixtureと、少なくとも次のテストを作成します。

- URLの一致と拒否
- 正常な発見処理
- 必要な場合の複数ページまたはカーソル
- 安定IDの重複
- 空のコレクション
- 壊れたデータまたは上流構造の変更
- 必要な場合のレート制限と有限回の再試行
- 安全なファイル名と秘密情報のマスキング
- サイトから判定可能な場合のDRMまたは非対応配信検出

リポジトリのフォーマッター、リンター、型検査、テスト、パッケージ検査、ドキュメント検査を実行します。未検証のOS対応を断定しません。

### 5. 危険度の低い順に検証する

次の順序で、利用者が許可した段階まで実行します。

1. 匿名化fixtureを使った単体テスト
2. `archiveloom inspect`による発見結果の確認
3. `archiveloom download <URL> --output <PATH> --check-only`
4. 明示的に許可された場合だけ代表1件を試験保存
5. 別途明示的に許可された場合だけ全件実行

発見件数、表示名、ファイル名、プロトコル、除外理由が調査結果と一致することを確認します。fixtureテストだけで、アダプターが完成したとは表現しません。

### 6. 利用者へ引き渡す

次を分けて報告します。

- 外部状態が変わり得る場合は調査時刻を添えた検証済み事実
- 未検証または非対応の挙動
- 追加・変更したファイル
- テストと検査結果
- 正確なアダプターインストールコマンド
- 正確な`inspect`コマンド
- 正確な`--check-only`コマンド
- 利用者自身が開始する正確なダウンロードコマンド
- 中断または上流構造変更時の安全な復旧方法

Cookie、トークン、署名付きクエリなどの秘密情報を報告へ含めません。

## 完了条件

次を満たした場合だけ完了です。

- アダプターが意図したサイト範囲だけを認識する。
- 発見処理が有限で、構造変更を空一覧と誤認しない。
- 安定ID、安全なファイル名、有用な選択用分類を返す。
- 秘密情報を保存せず、正常系と異常系をテストしている。
- 実サイト検証が許可された場合、`inspect`と`--check-only`を実行している。
- 再現可能なインストール・実行コマンドを利用者へ提示している。
- 全件ダウンロードの開始が利用者の明示的管理下にある。

サイトへ安全かつ安定して対応できない場合は、確認済みの阻害要因を説明して停止してください。回避しないでください。
